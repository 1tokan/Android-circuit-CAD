# Pocket EDA

Androidで動く電子回路・PCB設計CAD（PWA）。最終目標は、LCSCの部品で回路図とPCBを設計し、JLCPCBに発注できるGerber・BOM・CPLを生成することです。

**現在: 第11段階（電流と配線幅の検査・部品番号の自動配置・サンプルの見直し）**。設計から JLCPCB への基板製造・部品実装の注文データまで作れます。Android の実機での操作性の確認は docs/DEVICE_TEST.md の手順で行ってください。

## 第11段階: 電流と配線幅・部品番号の自動配置・サンプルの見直し

### 電流と配線幅（「検査」タブ → DRC の「電流」）
- ネットごとに流れる最大の電流（A）と、許す温度上昇（既定 10℃）を入れると、**IPC-2221 の近似式**で必要な配線幅を外層・内層別に表示（銅厚は製造仕様の値）。ビア1本の許容電流の目安（めっき 18µm で計算）も出す
- DRC に2項目を追加
  - **配線幅（track_current）**: 電流を決めたネットで、必要な幅より細い配線を、ネット・層ごとに「本数・一番細い幅・その幅で流せる電流」と一緒に警告
  - **ビア（via_current）**: 電流に対してビアの本数が足りないネットを警告
- **自動配線もこの幅で引く**（必要な幅より細くしない）
- 検査しないもの（結果の「未検査の項目」にも表示）: 電流を決めていないネット、ベタ（内層の面）の電流容量、部品の定格・ノイズ・発熱（データシートでの確認が必要）。式は IPC-2221 の近似で、実際の温度は周囲の銅や部品の発熱で変わります

### 部品番号の位置を整える（PCB の選択ツールのチップ）
- パッドにかかる・基板からはみ出す部品番号を、部品の外形枠の上・下・左・右のうち空いている所へ動かす（動かせる番号があるときだけ件数つきで表示）。位置は部品からの相対位置として保存するので、部品を動かしても付いてくる

### サンプル（USB DAC アンプ）の見直し
- **スピーカー電源をロードスイッチ（TPS22918、ソフトスタート約 2.5ms）の後ろへ**。VBUS に直接つながる容量を 4µF にして、USB 2.0 の上限（10µF）に収めた。スピーカーは ESP32 が電源を入れるまで止まる
- **スピーカーアンプのゲインを 3dB に**（100k でプルアップ）。最大の出力を抑えて USB の 500mA に収める
- **USB-C の CC1/CC2 を ESP32 で読み**、電源の能力（Default／1.5A／3A）に合わせて音量の上限を決められるようにした（ファームウェア側の処理は未作成）
- **ヘッドホン出力に ESD 保護**（PESD5V0S1BLD ×2）
- 電流を設定: VBUS 0.5A・+5V_SPK 0.4A・スピーカー出力 0.25A など。**配線はすべて必要な幅以上**（最も細い 0.15mm で約 0.6A。スピーカーの配線抵抗は片側 約 55mΩ）
- ヘッドホンアンプの有効化を GPIO33（ピン 38）に移した（配線の都合）。全ネット配線済み・DRC エラー 0
- 未確定のもの（第10段階の分に加えて）: 374k（右チャンネル選択）の LCSC 品番、ESD 部品は SOD-882 の代わりに 0402 のランドで仮置き、LDO の出力側の突入電流は制限していない、USB の差動インピーダンスは管理していない

## 第10段階: 自動配線・長穴・サンプル（USB DAC アンプ）

### サンプルを開く（プロジェクト一覧の「サンプル」）
- 設計例「**USB DAC アンプ**」を同梱。開くたびに新しいプロジェクトとして追加するので、いじって試せます（元のサンプルは変わりません）
  - USB-C（バスパワー 5V）→ ESP32-S3FN8（USB オーディオ）→ I2S 32bit → PCM5102A（DAC）＋ TPA6132A2（ヘッドホン）／MAX98357A ×2（8Ω スピーカー L/R）
  - 60×20mm・4層（In1 = GND、In2 = 5V／3.3V／アナログ 3.3V に分割）。USB-C は左端、**スピーカー端子 L/R（JST PH 横向き）は右端**、**3.5mm ジャックは上の長辺から差し込む向き**（基板の長さを取らない）
  - 回路図 ERC エラー 0、PCB は**全ネット配線済みで DRC エラー 0**（警告: 端のコネクタのはみ出し・シルクの重なりなど）。主要部品は LCSC 品番つき
  - 未確定のもの: 一部受動部品（100k・210k・20pF）・LED・書き込み用パッドの LCSC 品番、ESP32-S3 のファームウェア（USB オーディオ UAC2。Full Speed のため 32bit は 96kHz まで）、ダンピングファクター（出力インピーダンス）の実測
- テスト: `tests/sample.test.mjs`（ERC・DRC・配置の要件・Gerber）、`tests/e2e-sample.mjs`（画面から開いて検査・出力・3D）

### 自動配線（PCB の「自動配線」）
- 未配線の接続を、設計ルールの間隔を守って格子上の経路探索（A*）で引きます。引けないときは、この実行で引いた配線をはがして引き直します。今ある配線・ビアは動かしません
- 使う層（表・裏／内層1枚も信号に使う）と線幅（信号・電源）を選べます。終わったら「元に戻す」で取り消せます。引けなかった接続は一覧で知らせます

### 長穴（スロット）
- フットプリントのパッドに長穴を指定できます（USB-C の固定足など）。Excellon は G85 で出力し、DRC の穴どうしの間隔も長穴の形で測ります

## 第9段階: Claude で回路を作る・多層基板と製造仕様・3D 表示

### Claude で回路を作る（メニュー、または回路図の「Claude で作る」）
- 作りたい回路を文章で書くと、Claude が部品（種別・値・パッケージ・LCSC 品番）とネット（どのピン同士をつなぐか）を決め、確認したいことがあれば質問を返す。返答はアプリ内の決まった形式（JSON）で受け取り、**「この回路図に作図」でシンボル・電源記号・ネットラベルを自動で配置**する（作図後に ERC を自動実行）
- 使い方は2通り
  - **API キーを使う**: Anthropic の API キー（従量課金）を入れて「Claude に送る」。モデルは Sonnet 5.5（既定）／Opus 5.5／Haiku 5.5。キーは「この端末に保存」を選んだときだけ端末に保存
  - **claude.ai のアプリを使う**: 「claude.ai 用にコピー」で依頼文をコピー → Claude のアプリに貼り付けて送る → 返ってきた JSON を「返答を貼り付け」
- 2回目以降は今の回路図を添えて送るので「この回路に〜を追加して」のような修正もできる。会話はプロジェクトに保存
- 内蔵部品に同じ LCSC 品番か同じ値・パッケージがあればそれを使い、無ければ部品データを作ってプロジェクトに追加（フットプリントはパッケージ名から選ぶ／自動生成）
- **AI の回路は必ず確認が必要**: 定数・ピン番号・部品選定はデータシートで確かめてください。ERC は接続の形式しか見ません

### 多層基板（4・6層）と JLCPCB の製造仕様（「出力」タブ →「製造仕様」）
- 層数 2／4／6。4層は F.Cu・In1.Cu・In2.Cu・B.Cu、6層は内層4枚。内層への配線・ベタ、ビアで層を移る（3層以上はビアを置くときに行き先の層を選ぶ）
- Gerber は内層を **.G1〜.G4**（X2: Copper,L2,Inr …）で出力。注文一覧に層の順序（GTL→G1→G2→GBL）を表示
- JLCPCB の注文フォームの項目をプロジェクトに保存: 板厚、積層構成（4層 JLC7628／JLC2313、6層 JLC2313）、外層・内層の銅厚、**レジスト色**（緑・紫・赤・黄・青・白・黒）、シルク色、表面処理（HASL 有鉛／鉛フリー・ENIG）、ビアの処理（テンティング／開口／穴埋め）。層数に合わない組み合わせ（例: 6層で HASL）は警告
- 設計ルールは層数で切り替え（4・6層は最小配線幅・間隔 0.09 mm、ビア穴 0.2 mm／外径 0.45 mm、内層の基板端クリアランス 0.4 mm）。利用者が変えた値だけを保存
- **レジストまわりの DRC**: パッド間のレジストのブリッジ（ダム）が 0.1 mm 未満になる所を警告。レジスト開口の拡大量 0.05 mm。ビアのテンティングは製造仕様の「ビアの処理」から決める
- 「JLCPCB への注文」に、注文フォームで選ぶ値の一覧（コピー可）

### 3D 表示（「出力」タブの「3Dで見る」）
- 基板（外形・板厚・全部の穴）に、製造データそのもの（レジスト色・レジスト越しの銅・パッドの表面処理の色・シルク）を貼り、部品を寸法とパッケージから作った**簡易形状**で載せる。1本指で回転、2本指で拡大・移動。表・裏・斜め、部品の表示切替
- 実物の 3D モデル（STEP）ではありません

### 整理したもの（重複・矛盾・欠落）
- **フットプリント 44 種を KiCad 公式ライブラリと照合**し、寸法を KiCad のデータに置き換え（SOT-23 などで内蔵の値がずれていた）。部品画面に「KiCad 公式と照合済み」と表示
- 設計ルールを1か所（`js/check/rules.js`）にまとめ、DRC・ベタ・Gerber が同じ値を使う。プロジェクトに既定値を丸ごと保存していたのをやめ、変えた値だけ保存（データ形式 v2、古いプロジェクトは自動で移行）
- 層数を PCB の設定1か所に（以前は板厚・銅厚と別々に持っていた）
- 同じ関数の重複（HTML のエスケープ、Union-Find、点と多角形の判定）を `js/core/util.js`・`js/core/geom2d.js` に統合
- 「Header 1xN」「JST PH nP」などのパッケージ名からフットプリントを選べるように
- 古くなった説明文（「寸法未照合」「第○段階で実装予定」など）を更新

## 第8段階: Android での試験と操作性の改善

- **Android エミュレータでの自動試験**（GitHub Actions、Android 11 / 14 / 15）: 実際の APK を入れて WebView に接続し、テスト回路 A〜E の通し（回路図 → ネットリスト → ERC → PCB → DRC → Gerber → BOM/CPL）、タッチでのタブ切替、Android の戻るボタン、ZIP の保存と共有画面、JavaScript エラーの有無を確認。結果と画面は `device-test-api30/34/35` ブランチ
- 試験で見つけて直したもの:
  - **Android 15 で上部のバーがステータスバーの下に隠れていた**（端から端までの表示の強制）→ システムバーの分だけ余白を付けるよう修正
  - **古い WebView（Chrome 98 未満、例: 更新していない Android 11）では真っ白**だった → 起動せずに「Android System WebView を更新してください」と案内
- **Android の戻るボタン**: ダイアログ・メニュー・ドロワーを閉じる → 操作中のツールを取り消す → 回路図へ戻る → 保存してアプリを背面へ（終了しない）
- **PCB「基板内に並べる」**: ネットリストを読み込んで基板の外に並んだ部品を、基板の中の空いている所へ詰めて置く（部品番号のシルクの分も空ける）
- テスト回路 A〜E（LED、非反転増幅、ESP32-S3、4ch マイク入力、USB 電源＋LDO）を `tests/scenarios.js` に用意し、Node と Android の WebView の両方で同じ通し試験を実行
  - ESP32-S3 は QFN-56 の IC として試験用に作ったもので、使うピン以外は未使用指定。モジュール（WROOM）や USB-C コネクタのフットプリントは内蔵していません（E の USB は4ピンヘッダで代用）
- 小さい画面（360×640）ではみ出さないこと、ツールボタンの高さ（40px 以上）を E2E で確認


## 第7段階: BOM・CPL（「出力」タブ →「部品実装」）

JLCPCB の部品実装（PCBA）の注文で、BOM と CPL の欄にそのままアップロードできる CSV を作ります（UTF-8・BOM付き、Excel でも文字化けしない）。

| ファイル | 列 | 内容 |
|---|---|---|
| `<名前>-BOM.csv` | Comment, Designator, Footprint, LCSC Part # | 同じ値・パッケージ・LCSC品番の部品を1行にまとめる（部品番号は自然順） |
| `<名前>-CPL.csv` | Designator, Mid X, Mid Y, Layer, Rotation | 部品の中心（mm）、面（Top/Bottom）、回転（反時計回りが正） |

- 座標は Gerber と同じ原点・Y 上向きです（テストで、メタルマスクのパッド位置から求めた中心と一致することを確認）
- **回転**: 「PCB での向き ＋ パッケージごとの補正 ＋ 部品ごとの手動補正」。パッケージ補正（SOIC 270°、SOT-23 180°、QFN 90° など）は KiCad 用の JLCPCB Fabrication Toolkit の表と同じ値です（内蔵フットプリントは KiCad 標準と同じ向きで作ってあるため）。裏面は「180° − 向き」。**JLCPCB の注文画面のプレビューで向きを必ず確認**し、ずれていたら部品実装の表の「±90」で直して書き出し直してください（PCB の履歴に入るので元に戻せます）
- 書き出し前の確認: LCSC品番の無い部品・部品番号の重複・基板外の部品はエラー（確認のうえ書き出し可）。DNP 部品は除外。Extended 部品・区分不明・裏面部品・補正表に無いパッケージは注意を表示
- 部品データに価格があれば、枚数に応じた**部品代の目安**を表示（送料・実装費は含まない）
- 内蔵部品には、確認していない LCSC 品番を勝手に入れていません。部品画面のオンライン検索（jlcsearch）で品番を付けてください


## 第6段階: ベタの塗りつぶし・Gerber・ドリル（「出力」タブ）

「出力」タブの「ZIPを書き出す」（または下の「Gerber書出」）で、JLCPCB の見積もりページにそのままアップロードできる ZIP を作ります。書き出す直前に DRC をやり直し、エラーがあれば確認を出します。プレビューは**書き出す図形そのもの**を層ごとに表示します。

| ファイル | 内容 |
|---|---|
| `.gtl` `.gbl` | 表・裏の銅箔（配線・パッド・ビア・ベタ） |
| `.gts` `.gbs` | 表・裏のレジスト開口（パッドより片側 0.05mm 大きく。ビアは既定で覆う＝テンティング） |
| `.gto` `.gbo` | 表・裏のシルク（部品外形線・1番ピンの印・部品番号・文字） |
| `.gtp` (`.gbp`) | メタルマスク（SMD パッド。裏に SMD が無ければ出さない） |
| `.gm1` | 基板外形 |
| `-PTH.drl` `-NPTH.drl` | メッキ穴（スルーホール・ビア）と非メッキ穴（取付穴）。Excellon・mm・小数表記 |

- Gerber は RS-274X（X2 属性つき）、mm、4.6形式。Y は上向き（基板座標を反転）。角丸・回転したパッドはアパーチャマクロ、ベタは領域（G36/G37）で、穴は clear で抜きます
- **ベタの塗りつぶしを実装**: 別ネットの銅・取付穴からクリアランス（既定 0.3mm）を抜き、同ネットのパッドにはサーマル（隙間 0.3mm・スポーク 0.35mm × 4方向）、同ネットのビアは直結。どこにもつながらない島は取り除きます。丸い形は外接多角形で近似するので、クリアランスが指定値より小さくなることはありません。PCB画面では編集の手が止まると塗り直し、ラッツネスト（未配線）も実際の塗りでつながっているかで判定します（以前の「推定」ではなくなりました）
- **シルク文字はストロークフォント**（Hershey Simplex、MIT/パブリックドメイン）で、画面表示と Gerber が同じ線です。部品番号は高さ 1.0mm・線幅 0.16mm。日本語など ASCII 以外の文字は出力できないため DRC でエラーにします
- DRC に追加: ベタの塗りつぶし結果の検算（別ネットとの間隔・埋まり）、取り除いた島、重なる別ネットのベタ、シルク文字の高さ・線幅（JLCPCB 最小 1.0mm / 0.153mm）
- **独立した実装での検証**: `tests/verify-gerber.mjs` で、書き出した ZIP を tracespace（whats-that-gerber・pcb-stackup）と Python の pcb-tools で読み直し、層の判定・外形寸法・穴の数と径を確認しています（KiCad GerbView はこの環境に無いため未使用）
- 未対応: 基板外形の長方形以外の形、ベタの細いくびれの除去（長穴は第10段階、レジストのブリッジ幅は第9段階で対応）


## 第5段階: ERC・DRC（「検査」タブ）

下のツールの「ERC実行」「DRC実行」で検査します。結果は一覧（エラー／警告で絞り込み）で表示し、「表示」で回路図・PCBの該当位置へ移動して印を出します。結果はプロジェクトに保存され、回路図・PCBを変更すると「古い結果」と表示します（古い結果を最新のように見せない）。**どの結果にも「検査した項目」と「検査していない項目」の一覧が付きます。**

| ERC（回路図） | DRC（PCB） |
|---|---|
| 部品番号の形式・未採番・重複 | 配線幅、ビアの外径・穴径・ランド幅、スルーホールの穴径・ランド幅 |
| 未接続ピン（入力・電源ピンはエラー。未使用ピン指定は除外） | 異なるネットの銅の短絡・間隔（配線・パッド・ビア、層ごと） |
| 未使用指定のピンの接続、ピン1つだけのネット | 基板外形と銅の間隔、基板外の銅 |
| 電源入力ピンに電源がない、出力どうし・電源出力どうしの衝突 | 穴どうし（異なるネット）、取付穴と銅 |
| 入力だけのネット、電源ピン名とネットの食い違い（VCCピンがGNDに等） | 未配線（ラッツネスト）、浮いた配線端、配線のネットの食い違い |
| ネット名の衝突、異なる電源記号の短絡（+5V と GND など） | 基板外・はみ出した部品、同じ面の部品の重なり |
| 浮いたネットラベル・電源記号・配線端 | シルクとパッドの重なり（文字幅は推定）、基板外のシルク、回路図との不一致、未照合フットプリント |

- **DRCの既定値**は JLCPCB 1〜2層標準品の製造能力（最小配線幅/間隔 0.127mm、パッド-配線 0.2mm、ビア穴 0.3mm・外径 0.5mm、PTHランド 0.13mm、穴径 0.2〜6.35mm、異ネット穴間 0.5mm、取付穴-銅 0.254mm）。「ルール」で変更できます
- **未検査（結果にも表示）**: ベタとほかの銅の間隔・島切れ（第6段階の塗りつぶし計算まで。ベタ経由の接続は推定扱い）、ソルダーマスク・メタルマスク、シルクの線幅・文字高さ、スリバー、3D干渉、差動・等長。ERCは1シートのみで、汎用ICのピン属性は部品データに無いため「双方向」扱い（入出力の衝突は検出できません）
- シルクの部品外形線はパッドの周り（0.15mm）で切って描くようにしました
- 修正: ピンヘッダのフットプリントのピッチが誤っていた（2.54mm にならず重なっていた）不具合を修正。PCBの「ネットリスト再読込」で、配置済み部品の形も新しい定義に更新されます（変更は読込結果に表示）。自動生成の QFN/DFN は角のパッドどうし・露出パッドとの間隔を 0.2mm 以上確保するよう修正し、QFN のピッチ推定を実在品に合わせました（QFN-20 4×4 → 0.5mm）


## 第4段階: PCBレイアウトエディタ（2層）

| 機能 | 操作 |
|---|---|
| ネットリスト読込 | 「ネットリストを読み込む」。回路図が変わっていれば自動で作り直す。部品は基板の下に並び、再読込しても配置済みの位置は保つ（回路図の部品IDで対応づけ） |
| 部品の配置・回転・裏返し | ドラッグ（0.25mmグリッドに吸着）、「回転」「裏返す」、長押しの属性で座標・任意角度・実装面・ロック |
| 配線 | 「配線」→パッド・配線端・ビアをタップして開始→次の点をタップ。**45°が基本**（90°・自由に切替、直線→斜め／斜め→直線を切替）。同じネットのパッドに着くと自動終了。**別ネットのパッドには接続させない** |
| ビア・層移動 | 配線中に「ビアで層移動」。単独で置く「ビア」ツール。層の切替は「層: 表/裏」 |
| 配線幅 | 0.15〜1.0mm から選択（既定は設計ルールの値） |
| ベタ（GNDポリゴン） | 「ベタ」→ネット（既定GND）と層（表・裏・両面）を選ぶ。基板外形から縁のクリアランス分内側に作成 |
| 基板外形・取付穴 | 「外形」で幅×高さ（mm）、「取付穴を追加」でタップ位置に穴（既定3.2mm） |
| シルク文字 | 「文字」→タップして入力（表/裏） |
| ラッツネスト | 未配線の接続を点線で表示。配線済みのネットは除外。**未配線数**と**短絡の疑い**（別ネットのパッドが銅でつながっている）を常時表示 |
| 元に戻す | 回路図とPCBで別々の履歴 |

- 内部座標は nm 整数。部品ごとに、ネットリスト読込時点のフットプリント定義を保存（後でフットプリントの定義が変わっても配置済みの形は変わらない）
- 接続は配線のネットではなく形状から計算（配線の端点がパッド・他の配線・ビアの銅箔内にあるか）
- **ベタは推定**: 範囲内の同ネットのパッドはつながるとみなす。他ネットとのクリアランスを抜いた実際の塗りつぶし形状と島切れの検査は第5・6段階
- 自動配線は第10段階、3D表示は第9段階で対応


## 第3段階: 部品ライブラリ・LCSC部品・ネットリスト

**LCSC公式APIは使いません**。APIは存在しますが、申請制で secret による署名が必要なため、サーバーを持たないPWAには安全に組み込めません（docs/ROADMAP.md）。代わりに次の方式で部品を扱います。外部サービスが使えなくても内蔵部品で設計を続けられます。

| 方式 | 内容 |
|---|---|
| CSV取込 | JLCPCB部品ライブラリのCSV、CDFER/jlcpcb-parts-database のCSV、jlcparts形式、日本語見出しの自作CSV。列名の表記ゆれ（`LCSC Part` / `JLCPCB Part #` / `lcsc` など）を吸収し、カテゴリ・説明からシンボル種別、パッケージからフットプリントを推定 |
| JSON取込・書出 | 部品ライブラリを `pocket-eda-library` 形式でやり取り |
| 手動登録・編集 | 名称・種別・値・メーカー・型番・LCSC品番・パッケージ・フットプリント（内蔵 or 独自JSON）・ピン→パッド対応・データシート・JLCPCB区分・価格・在庫・電気的仕様 |
| LCSC/JLCPCBへのリンク | 部品詳細から商品ページを開いて価格・在庫・品番を確認 |
| **オンライン検索（jlcsearch）** | 申請不要。部品画面の「オンライン検索」で、型番・LCSC品番・値から JLCPCB 部品を検索し、LCSC品番・価格・在庫・Basic/Extended区分を取得して端末のライブラリに保存 |

### オンライン検索（jlcsearch）について
- [jlcsearch](https://docs.tscircuit.com/web-apis/jlcsearch-api) は tscircuit が公開しているコミュニティAPI（認証不要）で、KiCad の JLCPCB プラグインと同じく yaqwsx/jlcparts の部品データを元にしています。**LCSC公式ではありません**
- 送るのは検索語だけ。呼び出しは0.7秒以上空け、同じ検索は10分キャッシュ
- 保存済みの部品を検索結果から保存し直すと、利用者が決めた種別・フットプリント・ピン対応は残し、価格・在庫・区分だけ更新
- つながらないときはエラーを表示し、内蔵部品・CSV取込で作業を続けられる
- スマホのブラウザから直接つながらない（CORSで拒否される）場合は、Cloudflare Workers に中継を置いて「設定」でURLを指定（[docs/jlcsearch-relay.md](docs/jlcsearch-relay.md)）

- 検索: 名称・メーカー型番・LCSC品番・パッケージ・値・電気的仕様。値の表記ゆれを吸収（`0.1uF` = `100nF`、`10KΩ` = `10k`）。種別・JLCPCB区分・在庫ありで絞り込み
- 部品データはシンボルとフットプリントを別々に持ち、**ピン番号↔パッド番号の対応**を保持。対応の誤り（パッドが無い・存在しないパッド・1パッドに複数ピン）を検出
- 内蔵フットプリント: チップ部品（0402〜1206）、SOD-123/323、SMA、SOT-23/23-5/223、SOIC/TSSOP/DIP、ピンヘッダ、JST PH、SMD電解、タクトスイッチなど。寸法は IPC-7351 / KiCad の公称値に合わせているが、**第6段階で KiCad 公式データと照合するまで「寸法未照合」と表示**
- **フットプリントの自動生成**: 内蔵に無いパッケージは、LCSC/JLCPCB のパッケージ名（`QFN-56-EP(7x7)`、`SOP-8_L4.9-W3.9-P1.27-LS6.0-BL`、`LQFP-48(7x7)`、`TSSOP-20`、`SOT-23-6`、`SOD-123F`、`2512`、`CASE-B-3528`、`SMD,D8xL10.2mm`、`HDR-F-2.54_2x5` など）を読んで標準寸法から生成。名前に寸法（P=ピッチ、W=本体幅、LS=端子先端間、(WxH)=本体）があればそれを優先。**推定なので「FP推定」「要確認」と表示し、発注前にデータシートの推奨ランドとの照合が必要**。モジュール・USBコネクタなど名前から形が決まらないものは生成しない（未設定のまま）
- IC・コネクタのピン数はフットプリントのパッド番号数に合わせる（露出パッド・タブを含めて食い違わないように）
- 内蔵部品のLCSC品番は、確認できたもの以外は「要確認」と表示。LCSCページで確認して「確認済み」にできる
- 回路図へは「回路図に配置」、既存の部品には属性の「ライブラリから選ぶ」で割り当て。使った部品データはプロジェクトにコピーされ、プロジェクト単体で完結
- **ネットリスト**（メニュー → ネットリスト）: 「部品番号-パッド番号」単位の接続を生成してプロジェクトに保存。部品番号の重複・フットプリント不明・ピン対応の誤り・ネット名の衝突はエラー、未接続ピン・LCSC品番未設定などは警告。回路図を変えると「古い」と表示。JSON・テキストで書き出し可

### 第3段階で直した不具合
- 自動保存の待ち時間（1.5秒）中にページを再読込・終了すると変更が失われていた → 閉じる瞬間に未保存分を localStorage に退避し、次回起動時に復元


## 第2段階: 回路図エディタ

| 操作 | スマホ（タッチ） | タブレット＋マウス/ペン |
|---|---|---|
| 部品の配置 | 「部品」→一覧で選んでキャンバスをタップ、または一覧からキャンバスへドラッグ | 同左（キー `P`） |
| 選択 | タップ。「複数選択」ONでタップごとに追加・解除 | クリック、Shift/Ctrl+クリックで追加 |
| 範囲選択 | 長押ししてからドラッグ | 空白をドラッグ |
| 移動 | 部品をドラッグ（グリッドに吸着、つながった配線は直角を保って追従） | 同左 |
| パン／ズーム | 空白を1本指ドラッグ／2本指ピンチ | 中ボタン・右ボタンドラッグ／ホイール |
| 回転・ミラー・削除 | 下部ツール、または上部のチップ | `R`・`M`・`Delete` |
| 配線 | 始点→次の点をタップ。ピン・配線・ラベルに着くと自動終了。曲げ方向は切替可 | 同左（キー `W`） |
| 配線の分岐 | 既存配線の途中から引き出す（分岐点で配線を分割し、接続ドットを表示） | 同左 |
| ネットラベル | 「ラベル」→配線やピンの上をタップして名前入力 | キー `L` |
| GND・電源記号 | 「電源」→ VCC / +5V / +3V3 / GND など | 同左 |
| 属性編集 | 長押し、または「属性」チップ | ダブルクリック、キー `E` |
| 元に戻す・やり直す | 上部の ↶ ↷ | `Ctrl+Z` / `Ctrl+Y` |

- 部品番号は種別ごとに自動採番（R1, C1, D1, Q1, U1, J1, SW1, BT1…）。メニューから位置順に振り直し可
- 初期対応部品: 抵抗、可変抵抗、コンデンサ、電解コンデンサ、インダクタ、ダイオード、LED、ツェナー、NPN/PNPトランジスタ、Nch/Pch MOSFET、オペアンプ、汎用IC（ピン数・ピン名を指定）、コネクタ（ピン数指定）、スイッチ、電池・電源、電源記号、GND
- 各ピンに番号・名前・電気的属性（入力/出力/双方向/電源入力/電源出力/パッシブ）を定義
- **接続の扱い**: 配線は電気的接続として計算する。端点が他の配線上・ピン上にあれば接続、線の途中同士の交差は非接続。3本以上集まる点にだけ接続ドット。同名のネットラベル・電源記号は離れていても同じネット
- 未接続のピン先端は赤い丸で表示。メニュー「接続一覧（確認用）」で計算結果を確認できる（製造用ネットリスト出力は第3段階）
