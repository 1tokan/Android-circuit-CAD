# 第8段階: Android 実機での確認手順

自動試験（GitHub Actions の Android エミュレータ、Chrome のスマホ表示）で確かめられない「手で触った感じ」を実機で確認するための手順です。結果（気になった点・画面のスクリーンショット）を送ってもらえれば直します。

## 準備

1. 最新の APK（`pocket-eda-<版>.apk`）を入れる。前の版が入っていれば上書き更新でよい
2. 起動して、右上のメニュー →「このアプリについて」で版を確認

## 確認する操作（テスト回路 A〜E）

| # | 操作 | 期待どおりか見る点 |
|---|---|---|
| 1 | 新規プロジェクトで テストA（JST 電池 → 330Ω → LED → GND）を回路図に描く | 部品の配置・回転・配線が指で狙いどおりにできるか。拡大縮小（ピンチ）とパン（ドラッグ）が引っかからないか |
| 2 | 部品画面で LED などを検索・オンライン検索（jlcsearch）で LCSC 品番を付ける | 文字入力・一覧のスクロール・結果の読みやすさ |
| 3 | 検査タブで ERC を実行し、「表示」で回路図の位置へ移動 | 印の位置が正しいか |
| 4 | PCB タブで「ネットリストを読み込む」→「基板内に並べる」→ 配線 → ベタ | 配線の始点・終点のタップのしやすさ、ベタの塗り直しの待ち時間 |
| 5 | DRC を実行し、指摘を直す | エラー位置へのジャンプ |
| 6 | 出力タブで Gerber ZIP・BOM・CPL を書き出す | 共有画面が開き、Google ドライブ・ファイルアプリに保存できるか |
| 7 | 保存した ZIP を JLCPCB の見積もりページ（スマホのブラウザ）でアップロード | 基板の画像・寸法が正しく出るか（注文はしなくてよい） |
| 8 | Android の戻るボタン（戻るジェスチャー） | ダイアログ・メニュー・ドロワーが閉じる → 操作中のツールが取り消される → 回路図へ戻る → アプリが背面へ（終了せず、次に開くと続きから） |
| 9 | 画面の回転（横向き）、文字サイズを大きくした設定 | はみ出し・重なり |
| 10 | 機内モードで起動・編集・保存 | オフラインで使えるか |

テスト B〜E（非反転増幅、ESP32-S3、4ch マイク、USB 電源＋LDO）は部品数が多いので、配置・配線のしやすさと動作の重さを見てください。

## 自動試験で確認していること

- **Android エミュレータ（API 30 = Android 11、API 34 = Android 14）**: 実際の APK を入れて WebView に接続し、テスト A〜E の通し（回路図 → ネットリスト → ERC → PCB → DRC → Gerber → BOM/CPL）、タブのタッチ切替、Android の戻るボタン（ドロワーを閉じる・回路図へ戻る・背面へ）、ZIP のファイル保存と共有画面、JavaScript のエラーが無いこと。各工程の時間を記録（`device-test-api*` の成果物の report.json）
- **Chrome のスマホ表示（390×844、360×640）**: 全画面のタッチ操作、はみ出し、ボタンの大きさ（高さ40px以上）
- エミュレータは PC の CPU で動くため、**処理時間は実機の目安にはなりません**。重さは実機で確認してください
